Вопросы

Задать вопрос на GitHub
Что означает self-hosted?+

Вы устанавливаете PushDocs на своём сервере и сами управляете CMS: обновлениями, резервными копиями, подключениями к репозиториям и доступами пользователей.

Как PushDocs работает с Docusaurus?+

Docusaurus отвечает за сайт документации, а PushDocs редактирует его содержимое. CMS работает со страницами Markdown и MDX в существующем проекте.

Могу ли я создать базу знаний для своего продукта?+

Да. Сначала создайте сайт на Docusaurus, затем подключите его к PushDocs. Например, это может быть база знаний конструктора, помощь пользователям или внутреннее руководство команды.

Что происходит после отправки правок?+

PushDocs отправляет документы и вложения в репозиторий и создаёт запрос на проверку: pull request в GitHub или merge request в GitLab. Команда принимает изменения там. Затем существующий процесс публикации вашего проекта обновляет сайт. Сохранение черновика в PushDocs само по себе не публикует страницу.

Где хранятся мои документы?+

Исходники остаются в вашем Git-репозитории. Черновики, комментарии и загруженные до отправки файлы хранятся на сервере PushDocs. Изменения попадают в Git, когда редактор явно отправляет их.

Можно ли редактировать текст как в Word?+

В текущей версии текст редактируется в Markdown или MDX: есть кнопки для заголовков, жирного текста и таблиц, загрузка изображений и предпросмотр страницы. Это не полный визуальный редактор Word. Для ежедневной работы терминал не нужен; установку и подключения настраивает администратор.

Можно ли увидеть сайт до отправки в Git?+

Быстрый предпросмотр показывает Markdown без выполнения MDX-компонентов. Администратор также может настроить живой предпросмотр Docusaurus-сайта с сохранёнными черновиками и вложениями.

Что уже работает, а что ещё в разработке?+

Слияние выполняется в GitHub или GitLab. Актуальные возможности и ограничения перечислены в README проекта.
